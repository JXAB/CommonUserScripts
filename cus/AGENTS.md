# AGENTS.md — Coding Agent 工作边界与交付验收

## 允许区域

只能在本项目根目录内读写代码、文档、测试和测试 fixture。访问用户其它目录（如 `$HOME/.ssh`、密钥文件、浏览器缓存、其他私有库）必须先征得授权。执行 CI 前优先使用隔离临时目录和模拟系统命令。

## 禁止事项

- 不准使用 `curl|bash`、`wget|sh`、`--no-check-certificate`、`sudo bash <url>` 作为默认执行方案；下载外部脚本要固定 URL/版本+哈希并供用户审查。
- 不准执行破坏性全局删除 (`rm -rf /...`、无限定 glob、卸载用户已有软件)、未授权 apt upgrade/dist-upgrade、关闭 SSH、全端口放行、修改云安全组。
- 不准读取/打印/上传 Token、API key、Cookie、密码、私钥、用户 `.env`；不在日志、PR、报告里公开 secrets。
- 不准以 root 身份运行整个 Agent；不得让 Agent 自动接受系统危险操作。
- 不准修改属于其它 Agent 项目的文件；不得在外部目录执行 git reset、clean、force push。
- 不准安装未经验证的第三方源包或绕过系统证书链。
- 不准在“未测试、未编译、未上传”时宣称成功；对没有工具执行证据的步骤标记 NOT VERIFIED。

## 权限等级

L0 只读：status、doctor、check、plan —— 默认可执行。
L1 用户范围：创建项目目录、安装用户级工具 —— 显式授权。
L2 系统范围：apt/dnf/winget、安装服务 —— 显式授权 + 权限升级确认。
L3 高风险：清理、覆盖配置、迁移数据库、SSH/防火墙、外部可访问 API —— 独立二次确认并备份可恢复文件。
L4 破坏性操作：格式化、全盘删除、重置、关闭救援通道 —— 不由本工具执行。

## 交付门禁

1. 给出修改清单及所需权限和风险。
2. 先写测试，再做实现。
3. 静态检查、单元测试、模拟集成测试、目标平台实机验收。
4. 每项实现须给出实际命令、退出码、输出的摘要以及目标能力验收。
5. 对未满足的条件诚实标注 TODO/BLOCKED/UNVERIFIED；不可仅打印 PASS。
6. 不为了“全绿”删除失败测试或跳过验证。
7. 修改远程仓库需要用户显式批准；生成 ZIP、提交到本地 Git 不等于已上传 GitHub。

## 第三方来源

固定 release tag 或 commit SHA；下载文件校验 SHA-256，来源域名白名单；产出 SBOM/来源清单；只在用户明确启用后运行。主菜单模块插件不能任意执行元数据里拼接的 shell 字符串，应使用结构化 argv 和受控适配器。
